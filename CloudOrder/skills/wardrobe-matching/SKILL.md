# 衣柜搭配流程

**核心铁律：搭配只能从「衣柜」数据库里挑选单品，绝不能编造衣柜里没有的衣物。**

## 步骤

1. **先读衣柜**：调用 `wardrobe_list` 查看当前可用单品。
   - 需要筛选时传入 `category` / `color` / `season` / `style` / `keyword`，减少上下文噪音。
   - 需要某件单品的完整参数（材质、版型、尺码、备注）时，用 `wardrobe_get` 按 `id` 读全文。

2. **衣柜为空时**：不要硬编方案。
   - 明确告诉用户："你的衣柜还没有录入任何衣物，请先在网页版右上角的「衣柜」入口添加单品（名称、类别、颜色、材质、季节、风格，可上传图片），之后我就能按你真实的衣服来搭。"
   - 如果用户愿意，也可以让他们用自然语言描述衣物，你用 `wardrobe_add` 帮其录入（录入前先确认关键参数，避免记错）。
   - **如果用户有衣物图片**（他自己发的、或之前录入时上传的），可以先用 `analyze_image`（`mode=clothing`）识别出类别/颜色/材质等参数，确认后再 `wardrobe_add` 录入；图片本身需由用户在网页版「衣柜」入口上传。详细流程见 `wardrobe-vision` 技能。

3. **从衣柜中挑选**：
   - 结合场合 + 天气（`get_weather` / `get_weather_forecast`，必要时加载 `weather-dressing`）筛选合适的单品。
   - 每套方案里的每一件都必须能在衣柜中找到，并在方案中**标注该单品的名称（和 id）**，方便用户对号入座。
   - 呈现时可直接给出单品图片链接：`/api/wardrobe/image/<文件名>`（`wardrobe_list` / `wardrobe_get` 会返回），便于用户直观看到是哪件。

4. **缺件要明说**：如果某套理想方案需要衣柜里没有的单品，明确写出"衣柜里缺 XX（可到衣柜入口添加）"，把它作为**建议补充项**单独列出，而不是假装衣柜里有。

5. **输出格式**：

```
## 方案 A：<一句话定位>
- 上装：<衣柜单品名称>[<id>]
- 下装：<衣柜单品名称>[<id>]
- 鞋：<衣柜单品名称>[<id>]
- 配饰：<可选>
- 适合：<场合 / 温度>
- 取舍：<为什么这样搭>

## 方案 B：…

## 建议补充
- <衣柜里缺的单品>（可选，非必需）
```

6. **收尾**：一句话说明"如果只能选一套我会推荐哪套，为什么"。

## 规则

- 只用衣柜里的真实单品，不用通用描述搪塞。
- 用户说"我的衣服"时，先 `wardrobe_list`，不要凭记忆。
- 维护衣柜（新增/修改/删除）前先向用户确认关键参数；`wardrobe_remove` 属高风险操作，务必先确认。
- 回答使用与用户相同的语言，简洁、准确、诚实。
