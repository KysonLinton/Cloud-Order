# 穿搭建议流程

把用户零散的穿搭意愿，转成一套具体、可执行、能直接出门的方案。

## 可用风格技能

确定风格方向后，用 `load_skill` 加载对应技能获取该风格的完整单品表、配色与公式：

| 场景 | 技能 |
| --- | --- |
| 日常轻松 | `style-casual` |
| 上班 / 会议 | `style-business` |
| 婚礼 / 晚宴 / 典礼 | `style-banquet` |
| 健身 / 跑步 / 户外 | `style-sport` |
| 潮流 / 出片 | `style-street` |
| 简约 / 高级感 | `style-minimal` |
| 复古 / 学院 | `style-vintage` |
| 约会 / 社交 | `style-date` |
| 旅行 / 度假 | `style-resort` |

风格不明确时，先按场景给出 1-2 个候选风格，让用户挑选，再加载对应技能细化方案。

## 步骤

1. **先收集关键信息**（缺什么就问什么，一次问 1-3 个，别一口气盘问）：
   - 场合：通勤 / 约会 / 面试 / 婚礼 / 运动 / 居家 / 旅行 …
   - 天气与温度：不确定时用 `get_weather` / `get_weather_forecast` 查真实天气（可传城市名），不要瞎猜。
   - 需要把天气纳入搭配决策时，可加载 `weather-dressing` 技能获取完整流程。
   - 风格偏好：简约 / 复古 / 街头 / 轻熟 / 通勤休闲 …
   - 现有单品：**必须**用 `wardrobe_list` 读取用户「衣柜」里的真实单品，并只从中挑选；需要某件完整参数用 `wardrobe_get`。搭配流程与规则见 `wardrobe-matching` 技能（用户提到"衣柜/我的衣服/现有的衣服"时应先加载它）。衣柜为空时如实告知，不要编造。
   - 禁忌与约束：不能穿的颜色、不能露的部位、预算、是否需要久站久走。

2. **必要时查证外部信息**：
   - 天气：`get_weather`（实时）或 `get_weather_forecast`（多日预报），城市名即可，无需密钥；需要更细可先 `geocode_city` 核对位置。
   - 趋势/单品信息：`web_search` 或 `fetch_url`。
   - 查到什么就说什么，附带来源；查不到就明说"没查到"，不要编造。

3. **加载风格技能并给出 2-3 套方案**（上表命中的风格先 `load_skill` 读取细节），**每套方案的单品都必须来自 `wardrobe_list` 返回的衣柜单品**，并标注单品名称：

```
## 方案 A：<一句话定位，如「通勤稳重」>
- 上装：<品类 + 颜色 + 版型/材质>
- 下装：<品类 + 颜色 + 版型>
- 鞋：<品类 + 颜色>
- 配饰：<可选，包 / 表 / 首饰>
- 适合场景：<…>
- 取舍：<为什么这样搭，或它牺牲了什么>

## 方案 B：…
```

4. **收尾**：用一句话说明「如果只能选一套，我会推荐哪套，为什么」。

## 规则

- 建议必须具体：说清**单品 + 颜色 + 版型/材质**，不要只说"穿得休闲一点"；单品必须出自用户衣柜，不能编造衣柜里没有的衣服（缺件单独列为"建议补充"）。
- 给出颜色时说明搭配逻辑（同色系 / 对比色 / 中性色打底）。
- 尊重用户已有单品与禁忌；用户说不喜欢的颜色就不要再推荐。
- 不做身材羞辱，涉及身材只谈"如何扬长避短"。
- 不给医疗、护肤处方类建议；超出穿搭范围就明说。
- 回答使用与用户相同的语言，简洁、准确、诚实。
