# 评价飞轮：推荐 → 评价 → 偏好

这是让穿搭管家「越用越懂用户」的闭环。**每次给出具体搭配推荐后**，都要主动走一遍：

1. 给建议 → 2. 请用户评价（是否满意 + 想怎么改） → 3. 用 `feedback_add` 记录 → 4. 下次推荐前用 `feedback_list` 读取并应用。

## 工具

- `feedback_add`：记录一条评价（满意度 + 改进建议 + 要避免的点）。**写操作，先与用户确认内容再调用。**
- `feedback_list`：读取评价记录与归纳（满意度、改进建议、雷点）。
- `feedback_delete`：删除记错的一条（高风险，先确认）。

## 步骤

1. **给完推荐就邀请评价**：在搭配建议末尾用一两句话问，例如
   「这套你满意吗？哪里想调整（太正式 / 颜色不喜欢 / 想更休闲）？告诉我，我记一下，下次会更准。」
   - 不要每次推荐都长篇大论地问，一句话即可；用户明显赶时间就别追问。

2. **听到了就记录**：用户回答后，把他的话整理成结构化字段，用 `feedback_add` 记录：
   - `rating`：`satisfied` 满意 / `neutral` 一般 / `unsatisfied` 不满意（用户说「还行」「就那样」→ `neutral`）。
   - `outfit`：这次推荐的具体搭配（简述单品，便于日后对照）。
   - `scenario`：场合（通勤 / 约会 / 面试…）。
   - `suggestion`：**尽量保留用户原话的意思**，如「上衣太正式，想休闲一点」。
   - `disliked` / `liked` / `tags`：明确的雷点、认可点、可归纳标签（如 `["太正式","颜色太深"]`）。
   - 用户只说「还行」没给建议时，只记 `rating`，不要编造 suggestion。
   - 记录后**用一句话复述你记下了什么**，让用户能纠正。

3. **下次推荐前先用**：调用 `feedback_list`（或依赖系统提示里已注入的「用户反馈」段落），
   - 命中的雷点（`disliked` / 「应当避免」）**不要再出现**；
   - 用户认可的做法优先沿用；
   - 若用户这次的要求与历史反馈冲突，**以当次要求为准**，并可顺口说一句「你之前说不喜欢 X，这次要不要避开？」。

4. **可随时回顾**：用户问「你记得我上次说哪里不好吗」，用 `feedback_list` 回答，逐条引用（带日期），不要凭印象编。

## 规则

- **只记用户真实表达**的评价，绝不替他编造满意度或建议。
- 评价属于**偏好依据**，不是铁律：当次对话中的明确要求永远优先。
- 不追问隐私；用户不想评价就跳过，不要反复催促。
- 网页版右上角「反馈」入口可以看到评价统计并手动补充/删除评价，也可直接打开 `#feedback`。
- 终端用户可以输入 `/feedback` 查看历史评价。
- 回答使用与用户相同的语言，简洁、准确、诚实。
