# 衣物图片识别流程

把用户发来的衣服图片，转成可以直接录入「衣柜」的结构化参数。

## 工具

- `analyze_image`：调用多模态模型识别图片。
  - `mode=clothing`（默认）：识别衣物，返回**结构化 JSON**（name / category / colors / material / style / seasons / fit / brand / tags / notes / confidence / unsure），可直接对应衣柜字段。
  - `mode=describe`：只做通用图片描述。
  - `mode=custom` + `prompt`：按自定义要求分析（如"判断这件外套够不够保暖""这套搭配协调吗"）。
  - `image` 传图片路径：网页版上传的图片位于工作区 `uploads/` 目录，聊天记录中会附带具体路径（如 `uploads/u_xxx.png`）；衣柜图片为 `images/<文件名>.png`。也可直接传 http(s) 图片链接。

## 步骤

1. **拿到图片**：用户在网页版点「📎」附图后，系统会把图片存到工作区并给出路径；直接把该路径传给 `analyze_image`。
   - 用户只发图片没说话时，默认按 `mode=clothing` 识别，并主动问他"要不要录入衣柜"。

2. **识别**：调用 `analyze_image`（`mode=clothing`）。

3. **讲给用户听，先确认再录入**：
   - 用自然的语言复述识别到的关键参数（名称、颜色、材质、版型、适合季节），**不要直接把 JSON 甩给用户**。
   - 注意返回里的 `unsure` 字段：这些是模型没把握的项目，要明确说明"材质/品牌我拿不准，麻烦你确认"。
   - `confidence` 偏低时也要提示用户核对。

4. **录入衣柜**（用户同意后）：
   - 用 `wardrobe_add` 写入，参数取自识别结果 + 用户的口头修正。
   - **图片本身无法通过工具写入**：`wardrobe_add` 不接受图片。要告诉用户"图片请在网页版「衣柜」入口里上传/补图"，或引导他到 `#wardrobe/new`。
   - 一次识别多张图时，逐件确认、逐件录入，不要合并成一条。

5. **识别不出来时**：如实说明（如"这张图太暗/太糊/只是一段布料，我判断不了品类"），请用户换一张清晰图片，或用文字描述，绝不编造参数。

## 规则

- 只依据图片中确实可见的信息作答；看不清就留空并说明，不要臆测材质、品牌、价格。
- 识别结果属于"推断"，录入前必须经用户确认。
- 涉及人体身材的评价要克制，只谈"如何扬长避短"，不做身材羞辱。
- 回答使用与用户相同的语言，简洁、准确、诚实。
